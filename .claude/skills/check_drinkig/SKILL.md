# /check_drinkig — Drinkig 코드베이스 헬스 체크

Drinkig RN 앱의 전반적인 상태를 빠르게 진단하는 스킬입니다. 이 스킬이 호출되면 **아래 순서대로** 실행하고, 마지막에 한국어 요약 리포트를 출력하세요.

## 실행 절차

1. **디렉토리 구조 확인**
   - `src/` 이하 최상위 디렉토리 목록을 확인 (Bash: `ls src`).
   - `src/components/`, `src/screens/`의 파일 개수를 파악.
   - `CLAUDE.md`에 기술된 레이아웃과 실제 구조가 일치하는지 확인. 차이가 있으면 리포트에 경고.

2. **타입 체크**
   - `npx tsc --noEmit` 실행.
   - 에러가 있으면 파일별로 몇 건씩인지 집계.

3. **린트 체크**
   - `npm run lint` 실행 (eslint .).
   - warning / error 건수를 집계.

4. **테스트 상태 (선택)**
   - `__tests__/` 디렉토리에 실제 테스트 파일이 있는 경우에만 `npm test -- --passWithNoTests` 실행.
   - 테스트 파일이 없으면 "테스트 없음"으로 스킵.

5. **코드 컨벤션 스팟 체크**
   - `src/` 내에서 Grep: `t\(['"]` 호출 수 (i18n 사용 정도 지표).
   - `src/` 내에서 하드코딩된 hex 색상 Grep (`#[0-9a-fA-F]{6}`) → 개수만 집계해 테마 일관성 지표로 사용.

## 리포트 포맷

마지막에 다음 형식으로 **한국어** 요약을 출력:

```
## 🍷 Drinkig 헬스 체크 결과

- 📁 구조: <OK / 경고>
- 🧩 TypeScript: <에러 N건 / OK>
- 🧹 ESLint: <에러 N, 경고 M / OK>
- 🧪 Tests: <통과 N / 스킵>
- 🌐 i18n 호출: <N 회>
- 🎨 하드코딩 hex: <N 개>

### 주요 이슈
1. ...
2. ...

### 권장 조치
- ...
```

문제가 없으면 "✅ 이상 없음"으로 표시하세요.

## 주의

- 이 스킬은 **읽기 전용**입니다. 파일을 수정하지 마세요.
- 명령이 실패해도 다음 단계를 계속 진행하고, 실패 내용을 리포트에 포함하세요.
- 출력은 간결하게. 1000줄 넘는 raw 로그는 리포트에 붙이지 말 것.
